Prisma Agent Orchestrator API

Interact with high-throughput vector RAG pipelines, stream response tokens in real-time, and coordinate multi-agent worker nodes with enterprise zero-trust telemetry.

The Prisma Agent Orchestrator is designed for engineering teams deploying generative AI pipelines and autonomous agents in production environments. Built on an ultra-low-latency distributed edge architecture, the platform enables sub-10ms agent dispatch, automatic vector context routing, and granular observability over prompt token spend.

Authentication Header

All HTTP API requests require an API Bearer token passed in the standard HTTP Authorization header. API keys can be provisioned and rotated through your organization console or via the Prisma CLI.

Authorization: Bearer prisma_live_99a84b12c58e4d1f887201a09e

Every token is bound to a specific environment workspace (e.g., Development, Staging, or Production) and carries granular role-based permissions. If an expired or invalid token is supplied, the gateway returns an HTTP 401 Unauthorized response with a structured JSON error body.

Dispatch Agent Task

The Agent Dispatcher endpoint submits asynchronous inference tasks to specialized multi-modal agent workers. Requests support payload validation, contextual memory attachments, and dynamic temperature overrides.

POST /v1/agents/dispatch
{
  "agent_id": "rag-worker-01",
  "prompt": "Analyze vector embeddings for chunk #92",
  "max_tokens": 1024,
  "temperature": 0.2,
  "stream": false,
  "metadata": {
    "tenant_id": "org_48921",
    "cost_center": "mlops-platform"
  }
}

Response Payload

Successful dispatches return an instant HTTP 202 Accepted confirmation along with task execution metadata and a unique stream trace ID:

  "status": "queued",
  "estimated_latency_ms": 8.4,
  "worker_node": "edge-us-east-4a",

SSE Event Stream

For conversational interfaces and real-time generative output, subscribe to Server-Sent Events (SSE) using the streaming gateway. Each event packet delivers UTF-8 encoded token chunks and real-time cost telemetry.

GET /v1/agents/tasks/:task_id/stream
event: token
data: {"chunk": "Synthesizing", "index": 0}

event: token
data: {"chunk": " semantic", "index": 1}

event: token
data: {"chunk": " vectors...", "index": 2}

event: done
data: {"total_tokens": 42, "latency_ms": 114, "finish_reason": "stop"}

Clients should handle network reconnects gracefully. The stream includes an automatic exponential backoff header specifying retry recommendations should the HTTP connection terminate unexpectedly.

Official Client Libraries

Integrate Prisma Orchestrator seamlessly into your existing application stack using our officially supported TypeScript and Python SDKs. Each SDK includes automatic retry logic, type-safe streaming generators, and built-in distributed tracing.

Node.js & TypeScript

import { PrismaAgentClient } from '@prisma/agent-sdk';

const client = new PrismaAgentClient({
  apiKey: process.env.PRISMA_API_KEY,
  region: 'us-east-1'
});

const responseStream = await client.agents.dispatchStream({
  agentId: 'rag-worker-01',
  prompt: 'Synthesize quarterly latency metrics'
});

for await (const chunk of responseStream) {
  process.stdout.write(chunk.token);
}

Python (Asyncio)

from prisma_agent import AsyncPrismaClient

async with AsyncPrismaClient(api_key="prisma_live_...") as client:
    stream = await client.agents.dispatch_stream(
        agent_id="rag-worker-01",
        prompt="Analyze vector embeddings for chunk #92"
    )
    async for chunk in stream:
        print(chunk.token, end="", flush=True)

Error Handling & Diagnostics

All errors conform to RFC 7807 Problem Details specifications. When an API call fails, the response contains machine-readable diagnostic details along with a troubleshooting link:

{
  "type": "https://docs.prisma.io/errors/ERR_TOKEN_CAP_EXCEEDED",
  "title": "Rate Limit Exceeded",
  "status": 429,
  "detail": "Workspace token consumption exceeded tier threshold of 10,000 TPS.",
  "instance": "/v1/agents/dispatch",
  "retry_after_seconds": 3
}
